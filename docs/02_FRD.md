# 프렙 카페 운영 기록 프로그램 기능 요구사항(FRD) 초안

> 이 문서는 PRD의 필수 기능과 화면 시안의 버튼·입력칸을 기능 단위로 풀어 쓴다. 자료에서 확인된 사실, 시안에 보이는 요소, 계산·동작 제안, 미정 사항을 구분한다. 이 문서만 읽어도 주요 사용 흐름과 각 기능의 예상 입력·처리·결과·예외를 알 수 있도록 작성했다.

## 전체 사용 순서

1. 매장 운영자가 판매 또는 비용 기록을 직접 입력하거나, 제공된 엑셀 양식에 판매·비용·입고·폐기·실사 기록을 작성해 가져온다.
2. 저장된 판매 기록을 확인하고 잘못된 기록을 수정하거나 삭제한다. 일별 판매는 주문 한 건씩이 아니라 날짜·메뉴·채널별 합계로 기록한다.
3. 메뉴별 판매가와 직접 연결된 비용을 비교해 메뉴 수익성을 확인한다.
4. 일·주·월·분기·반기·연간 중 기간을 선택해 실제 실적과 기간 종료 시점까지의 예상 손익을 확인한다.
5. 재료의 입고·폐기·실사 수량과 판매에 따른 사용량을 반영한 잔량 및 발주 참고 정보를 확인한다.
6. 저장된 기록과 기준정보 전체를 백업하고, 필요할 때 백업 자료를 복원한다.

## 기능 목록

| ID | 기능 | 핵심 결과 |
|---|---|---|
| F-01 | 판매 기록 입력·수정·삭제 | 날짜·메뉴·채널별 판매량과 금액 저장 |
| F-02 | 비용 기록 입력·수정·삭제 | 날짜별 비용 저장 및 기간 손익 반영 |
| F-03 | 엑셀 양식 다운로드·기록 가져오기 | 판매·비용·입고·폐기·실사 기록 가져오기와 행별 오류 확인 |
| F-04 | 메뉴별 수익성 확인 | 메뉴·채널별 매출, 직접비용, 공헌이익과 이익률 확인 |
| F-05 | 기간별 실제·예상 손익 확인 | 선택 기간의 실적과 기간 종료 예상 손익 확인 |
| F-06 | 재고 기록·잔량·발주 참고 확인 | 입고·폐기·실사와 판매 사용량에 따른 재고 및 부족 참고 |
| F-07 | 전체 자료 백업·복원 | 거래·재고 기록과 프로그램 기준정보 보존·복원 |

## F-01. 판매 기록 입력·수정·삭제

### 사용자가 하는 일과 입력

- 대시보드 또는 판매 기록 화면에서 판매 입력을 연다.
- 시안에 보이는 입력은 날짜, 채널, 메뉴, 수량, 단가다. 여러 메뉴를 날짜·채널별로 기록할 수 있다.
- PRD에서 정한 기록 단위는 날짜·메뉴·채널별 하루 합계다. 주문 건수나 개별 주문은 입력하지 않는다.
- 기록 목록에서 기존 항목을 찾아 수정하거나 삭제한다.

### 프로그램이 하는 일

- 필수 입력 누락, 날짜 형식 오류, 등록되지 않은 메뉴·채널, 수량·단가의 잘못된 값 등을 확인한다.
- 유효한 기록을 저장하고 메뉴 수익성, 기간 손익, 재고 사용량 조회에 반영한다.
- 자료의 기존 판매 기록에 있는 당시 단가·할인·순매출·원가·수수료는 과거 시점의 값이다. 시안의 새 판매 입력에는 할인 입력란이 보이지 않으므로 새 기록의 할인 처리 기준은 미정으로 둔다.
- **계산 제안:** 새 기록의 매출은 입력 수량과 단가를 기준으로 하고, 직접비용은 해당 기록에 적용되는 레시피·포장비·채널 수수료 기준으로 산출한다. 과거 기록은 당시 기록값을 우선 보존해 현재 기준이 과거에 소급 적용되지 않도록 한다. 이 기준은 제안이며 최종 확정이 필요하다.

### 화면과 파일에 나오는 결과

- 저장된 날짜·메뉴·채널·수량·단가가 판매 기록 목록에 보인다.
- 메뉴 수익성, 기간 손익, 재고 사용량의 관련 값이 다시 계산되어 조회된다.
- 시안의 대시보드에는 오늘 매출·판매수량 요약이 있으며, 판매 입력 바로가기가 있다.
- 직접 파일을 내보내는 결과는 F-03의 엑셀 양식·가져오기를 따른다.

### 오류나 예외가 있을 때의 동작

- 필수값이 없거나 값 형식이 맞지 않으면 저장하지 않고 문제 항목과 수정 방법을 알린다.
- 수량이나 금액이 음수이거나 0일 때 허용 여부는 PRD·시안에 정해져 있지 않다. 임의로 확정하지 않는다.
- 이미 있는 날짜·메뉴·채널 조합을 다시 입력할 때 덮어쓸지, 별도 행으로 추가할지는 미정이다. 중복으로 인한 매출 이중 반영이 없도록 저장 전 확인이 필요하다.
- 삭제를 취소할 수 있는지와 삭제 후 재고·손익 재계산 방식은 상세 정책이 미정이다. 삭제가 연결 집계에 반영되어야 한다.
- 미마감일이나 미래 날짜의 빈 기록은 판매 0으로 간주하지 않는다. 실제 0 판매로 기록한 경우와 입력되지 않은 경우를 구분한다.

### 직접 확인할 방법

- 날짜·메뉴·채널 한 조합에 수량 5, 단가 100원을 저장해 목록에 5개와 500원이 보이는지 확인한다.
- 이 기록을 수정한 뒤 관련 메뉴·기간 조회가 바뀌는지, 삭제 후에는 빠지는지 확인한다.
- 필수 입력을 비우거나 잘못된 날짜를 넣었을 때 저장이 거부되고 안내가 보이는지 확인한다.

## F-02. 비용 기록 입력·수정·삭제

### 사용자가 하는 일과 입력

- 비용 기록 화면에서 날짜, 비용 항목, 금액 등 시안의 비용 입력칸을 작성한다.
- 기록 목록에서 비용을 찾아 수정하거나 삭제한다.
- 시안에는 임차료, 인건비, 관리비, 수도광열비, 광고비, 소모품 등의 비용 항목 예시가 있다. 자료의 실제 카테고리는 임차료, 인건비, 사업주 부담 보험료, 관리비, 수도광열비, 통신·소프트웨어, 광고비, 소모품·청소비다. 예시와 실제 분류의 차이는 분류 설정이 필요한 미정 사항이다.

### 프로그램이 하는 일

- 필수값, 날짜, 금액을 확인한 다음 유효한 비용 기록을 저장한다.
- 비용은 기간 손익의 공통비에 반영한다. PRD 기준으로 월세와 같은 공통비는 메뉴 수익성에 메뉴별로 배분하지 않는다.
- 원본에는 월비용계획 120건과 일별 비용기록 3,560건이 있다. 두 자료는 같은 지출의 월 단위·일 단위 표현이므로 둘을 실제 비용으로 합산하면 안 된다.
- **계산 제안:** 실제 손익은 비용기록을 사용하고, 예상 손익에는 마감일까지의 실제 비용과 남은 기간의 비용계획을 중복 없이 반영한다. 다만 월비용계획을 새로 입력·수정하는 기능은 PRD 필수 기능에 없으므로 입력 경로와 적용 방식은 미정이다.

### 화면과 파일에 나오는 결과

- 저장된 날짜·비용 항목·금액이 기록 목록에 보인다.
- 선택 기간의 공통비와 영업이익에 반영된다.
- 엑셀에서 비용기록을 가져온 경우 F-03의 가져오기 결과에 포함된다.

### 오류나 예외가 있을 때의 동작

- 날짜, 비용 항목, 금액이 빠지거나 형식이 잘못되면 저장하지 않고 해당 필드를 알린다.
- 음수 금액을 환불·정정으로 허용할지 여부는 미정이다.
- 같은 비용을 월비용계획과 비용기록에서 중복 반영하지 않도록 자료 출처와 기간을 구분한다. 계획과 실제가 겹치는 기간의 산정 기준이 확정되기 전에는 예상값의 기준을 명시해야 한다.
- 삭제·수정은 선택 기간의 집계에 반영되어야 하며, 이미 마감된 날짜의 수정 제한 여부는 미정이다.

### 직접 확인할 방법

- 공통비 120원을 입력하고 해당 기간 손익에 120원이 반영되는지 확인한다.
- 같은 비용을 수정·삭제하고 손익 집계가 각각 변경·제외되는지 확인한다.
- 계획비와 일별 비용이 함께 있는 기간에서 같은 지출이 두 번 합산되지 않는지 확인한다.

## F-03. 엑셀 양식 다운로드·기록 가져오기

### 사용자가 하는 일과 입력

- 대시보드 또는 기록 화면에서 엑셀 양식 다운로드를 선택한다.
- 양식에 판매·비용·입고·폐기·실사 기록을 작성하고 가져오기 화면에서 파일을 선택한다.
- PRD에서 메뉴·재료·레시피·공급사 같은 기준정보는 이 엑셀 가져오기 범위에서 제외한다.
- 시안에는 가져온 행별 미리보기와 오류 상태가 보인다.

### 프로그램이 하는 일

- 선택한 파일의 기록 유형과 각 행의 날짜·식별값·수량·금액 등 필수값을 확인한다.
- **오류 표시 제안:** 오류가 있는 행은 행 번호와 필드, 이유를 보여주고 사용자가 원본을 고칠 수 있게 한다. 오류 행 외에 정상 행을 먼저 반영할지, 오류가 하나라도 있으면 전체 반영을 중지할지는 시안·PRD에 명확히 정해져 있지 않아 미정이다.
- 원본 엑셀과 JSON은 동일 기록의 두 표현이다. 원본 샘플을 둘 다 가져오면 중복되므로 한 형식만 사용한다. PRD에서 제공하기로 한 가져오기 형식은 엑셀 양식이다.
- **중복 처리 제안:** 이미 가져온 파일·행과 동일한 기록을 다시 선택한 경우 중복 가능성을 알린다. 비교 기준과 중복 행의 자동 건너뛰기 여부는 미정이다.

### 화면과 파일에 나오는 결과

- 양식 파일이 내려받아지고, 양식에는 각 지원 기록 유형의 입력란이 제공된다. 정확한 시트·열 이름과 필수 항목은 별도 확정이 필요하다.
- 가져오기 미리보기에는 유형별 행 수와 행별 정상·오류 상태가 보인다.
- 처리가 완료되면 반영·보류된 행 수와 오류 목록이 보인다. 오류가 있는 파일은 오류 원인을 수정해 다시 가져올 수 있어야 한다.

### 오류나 예외가 있을 때의 동작

- 파일을 읽을 수 없거나 지원 형식이 아니면 가져오기를 시작하지 않고 지원 형식 안내를 표시한다.
- 필수 셀 누락, 날짜·숫자 형식 오류, 알 수 없는 메뉴·재료·채널, 단위 불일치를 식별해 행과 항목을 알려준다.
- 같은 판매·비용·재고 행이 반복되거나 원본 샘플의 두 형식을 함께 넣어 중복될 위험이 있으면 사용자에게 경고한다. 정확한 중복 판정 키는 미정이다.
- 가져오기 도중 일부만 반영된 경우 사용자가 어느 행이 저장되었는지 알 수 있어야 한다. 부분 반영 또는 전체 취소 정책은 확정 전이다.
- 빈 셀은 0과 다르다. 공란을 자동으로 0으로 채워 실제 0 기록처럼 만들지 않는다.

### 직접 확인할 방법

- 정상 행이 포함된 각 유형(판매·비용·입고·폐기·실사)의 파일을 가져와 해당 목록과 조회에서 확인한다.
- 날짜를 잘못 적은 행, 필수값을 비운 행을 포함해 오류 위치와 설명이 표시되는지 확인한다.
- 같은 자료를 다시 가져오거나 엑셀·JSON이 같은 자료임을 안내했을 때 중복 위험을 알아볼 수 있는지 확인한다.

## F-04. 메뉴별 수익성 확인

### 사용자가 하는 일과 입력

- 메뉴 수익성 화면에서 조회 기간 또는 메뉴·채널 조건을 선택한다. 시안에는 메뉴별 표와 채널별 비교 카드가 있다.
- 메뉴의 판매·레시피·포장 및 수수료 기준은 결과 해석에 필요하다. 메뉴·재료·레시피 기준정보를 등록·수정하는 화면은 PRD 필수 기능에 포함되지 않았으므로 기준정보를 어떻게 준비할지는 미정이다.

### 프로그램이 하는 일

- PRD 범위에 따라 메뉴에 직접 연결된 재료비·포장비·결제 수수료만 메뉴 비용으로 본다. 월세·인건비 같은 공통비는 여기서 메뉴별 배분하지 않는다.
- **계산 제안:** 메뉴 공헌이익(직접비를 빼고 남는 금액) = 순매출 − 재료비 − 포장비 − 채널 수수료. 공헌이익률 = 공헌이익 ÷ 순매출. 메뉴별 합계 공헌이익은 개당 공헌이익 × 판매수량으로 제안한다.
- 과거 판매에 저장된 당시 단가·할인·원가·수수료 기록은 과거 실적 계산에 우선 사용하고, 앞으로의 메뉴 비교에는 현재 기준 레시피와 가격을 쓰는 제안이다. 과거값과 현재값을 분리할 최종 기준은 승인 필요.
- 과거 기록에는 할인값이 있지만 시안의 신규 판매 입력에는 할인 입력란이 보이지 않는다. 할인 없는 새 입력과 할인 입력이 있는 과거 자료를 어떻게 같은 표에서 비교할지 미정이다.

### 화면과 파일에 나오는 결과

- 메뉴·채널별 판매가 또는 순매출, 재료비, 포장비, 수수료, 개당 공헌이익, 공헌이익률, 총 공헌이익을 표나 카드로 확인한다.
- **작은 계산 예시(시안의 일관된 메뉴 표 사례):** 판매가 4,091원, 재료비 522원, 포장비 110원, 수수료 115원이면 직접비는 522+110+115=747원, 개당 공헌이익은 4,091−747=3,344원, 공헌이익률은 약 81.7%다. 5개 판매라면 총 공헌이익은 3,344×5=16,720원이다.
- 위 숫자는 시안의 예시이며 첨부 매장의 실제 메뉴·가격이라는 뜻은 아니다. 메뉴·손익의 엑셀 내보내기와 PDF 인쇄는 시안에만 표시되고 PRD 필수 기능은 아니므로 MVP에 포함하지 않는다.

### 오류나 예외가 있을 때의 동작

- 레시피 또는 원가 기준이 없으면 수익성을 0원으로 단정하지 않고 계산 불가 또는 기준정보 부족으로 표시한다.
- 판매량이 없는 메뉴는 이익률을 0%로 표시하기보다 판매 없음·계산 불가 상태로 구분한다. 0으로 표시할지 공란으로 둘지는 미정이다.
- 순매출이 0 이하인 경우 이익률 분모가 성립하지 않으므로 이익률을 계산할 수 없다는 상태를 보여야 한다.
- 시안의 채널 비교 카드에는 구성 비용 합계와 표시 공헌이익이 서로 맞지 않는 사례가 있고, 채널별 수수료율도 `_1`~`_4`에서 서로 다르다. 이 불일치 사례를 계산 기준으로 채택하지 않으며 수수료 기준 확정이 필요하다.

### 직접 확인할 방법

- 위 예시 숫자를 넣어 직접비 747원, 개당 공헌이익 3,344원, 이익률 약 81.7%, 5개 총 공헌이익 16,720원이 일치하는지 확인한다.
- 공통비 120원을 더해도 메뉴 공헌이익이 바뀌지 않고 기간 손익의 공통비에만 반영되는지 확인한다.
- 레시피·수수료 기준이 비어 있는 경우 계산값을 허위로 만들지 않고 부족한 기준을 알려주는지 확인한다.

## F-05. 기간별 실제·예상 손익 확인

### 사용자가 하는 일과 입력

- 손익 화면에서 일·주·월·분기·반기·연간 단위와 조회 기간을 선택한다.
- 시안에는 매출·할인·순매출·직접비·공헌이익·공통비·영업이익의 요약과 실제·예상 비교가 표시되어 있다.
- 주의 시작일, 분기·반기 기준, 회계연도 시작월, 마감 기간 수정 가능 여부는 자료와 PRD에서 확인되지 않아 미정이다.

### 프로그램이 하는 일

- PRD에 따라 선택한 기간의 실제와 기간 종료 시점까지의 예상 손익을 구분한다.
- **계산 제안:** 순매출 = 총매출 − 할인. 공헌이익 = 순매출 − 직접비용. 영업이익 = 공헌이익 − 공통비.
- 예상 손익은 마감된 날짜의 실제값과 남은 날짜의 예상값을 합산하는 방식으로 제안한다. 시안은 과거 요일별 자료와 추세 가중을 언급하지만, 비교 기간·가중치·미마감일 처리 등 정확한 전망식은 정하지 않는다.
- 월비용계획과 날짜별 비용기록은 같은 비용을 다른 단위로 담은 데이터이므로, 실제값을 합산할 때 둘을 더하지 않는다. 제안은 실제 비용기록과 남은 기간 계획을 나누어 반영하는 방식이다.
- **작은 집계 예시:** 현재까지 실제 순매출 600원, 직접비 250원, 공통비 120원이면 현재 영업이익은 600−250−120=230원이다. 남은 기간의 예상 순매출 300원, 직접비 130원, 공통비 80원을 더하면 기간 종료 예상 영업이익은 (600+300)−(250+130)−(120+80)=320원이다. 이 예시는 집계 구조를 설명하며 전망값을 만드는 알고리즘은 확정하지 않는다.

### 화면과 파일에 나오는 결과

- 실제 누계, 남은 기간 예상, 기간 종료 예상 손익과 주요 구성 항목을 숫자와 시안의 그래프로 확인한다.
- 일부 기간만 자료가 있으면 전체 기간인 것처럼 보이지 않도록 자료 시작일·마지막 마감일 또는 집계 범위를 알린다.
- 첨부 자료는 2025-07-01~2026-09-18까지 마감되어 있고 달력만 2026-09-30까지 있다. 연간 조회는 완전한 1년이 아닐 수 있으며, 달력의 미래 날짜를 판매 0으로 간주하지 않는다.
- 손익 엑셀 내보내기·PDF 인쇄는 시안에만 표시되어 있고 PRD 필수 기능이 아니므로 MVP에서 제외한다.

### 오류나 예외가 있을 때의 동작

- 선택한 기간에 자료가 없으면 0 실적이라고 단정하지 않고 자료 없음으로 표시한다.
- 일부만 마감된 기간은 실적 구간과 예상 구간을 나누고 예상임을 표시한다.
- 계획과 실제 지출을 같은 기간에 이중 합산하지 않는다. 계획자료가 없거나 전망에 쓸 수 없으면 예상 공통비가 산출되지 않는 사유를 표시한다.
- 순매출·직접비·공통비 일부가 공란이면 0으로 간주하지 않고 불완전한 집계임을 알려야 한다.
- 시안의 예측 숫자는 그대로 계산 기준으로 삼지 않는다. 예를 들어 예측 공통비 항목 합계와 표시 소계가 1,700원(시안 금액 기준 1,700,000원) 차이 나는 사례가 있어 계산 검증이 필요하다.

### 직접 확인할 방법

- 위 작은 예시를 입력해 현재 영업이익 230원과 기간 종료 예상 영업이익 320원이 나오는지 확인한다.
- 같은 기간의 일별·월별 비용을 함께 준비해 비용이 중복 합산되지 않는지 확인한다.
- 자료가 없는 기간, 일부 날짜만 마감한 기간, 달력만 있고 판매 기록이 없는 기간을 각각 선택해 자료 없음·실제·예상의 구분을 확인한다.
- 일·주·월·분기·반기·연간을 각각 선택하고 선택 기간의 시작·끝이 사용자에게 드러나는지 확인한다. 기간 경계 규칙은 확정 후 검사한다.

## F-06. 재고 기록·잔량·발주 참고 확인

### 사용자가 하는 일과 입력

- 재고 화면에서 입고, 폐기, 실사 기록을 입력한다. 시안은 입고·폐기·실사 진입 버튼과 재료, 수량, 담당자, 메모 입력란을 보여준다.
- 기록 원본에는 날짜, 재료, 유형, 수량, 단위, 사유, 단가, 공급사, 실측 수량 등의 필드가 있다. 화면 시안과 원본의 입력란 차이는 상세 입력 항목 확정이 필요하다.
- 재고 현황에서 재료별 잔량, 최근 실사, 부족 예상 일수와 발주 참고 수량을 확인한다.

### 프로그램이 하는 일

- 입고는 양수, 폐기는 음수 재고 변동이다. 실사 수량은 실제로 센 수량이며 단순 증감값과 구분한다.
- PRD에 따라 발주 참고 계산에서는 가장 최근 실사 수량을 우선한다.
- **잔량 계산 제안:** 기준 실사 수량 + 이후 입고 − 이후 폐기 − 실사 후 판매량에 레시피를 적용해 산출한 재료 사용량. 초기 재고만 있고 실사가 없으면 초기 재고를 기준으로 한다.
- **발주 참고 계산 제안:** 목표 재고 − 예상 사용 가능 재고. 목표 재고는 공급사 납기 일수와 안전재고 일수 동안의 예상 사용량을 기준으로 하고, 부족량을 구매 포장 단위로 올림한다. 이 산식과 입고·폐기·실사 시점 처리 방식은 PRD에서 확정하지 않았으므로 검토용 제안이다.
- **작은 계산 예시:** 최근 실사 300ml + 이후 입고 100ml − 폐기 50ml − 실사 후 판매 사용량 150ml = 예상 잔량 200ml. 하루 사용량 100ml, 납기 2일, 안전재고 2일이면 목표량은 100×(2+2)=400ml. 부족량은 400−200=200ml다. 한 포장이 1,000ml라면 발주 참고량은 1포장이다.

### 화면과 파일에 나오는 결과

- 재료별 예상 잔량, 기준이 된 최근 실사 일자·수량, 입고·폐기·판매사용의 반영 범위가 보인다.
- 발주 참고에는 예상 부족량과 포장 단위로 환산한 참고 수량을 표시한다. 이는 자동 발주가 아니며 공급사에 주문을 전송하지 않는다.
- 시안의 재고 부족 일수·안전재고 상태는 이해를 돕는 참고 지표다.

### 오류나 예외가 있을 때의 동작

- 재료 또는 단위가 맞지 않거나 수량이 누락되면 저장·계산하지 않고 입력 오류를 알린다.
- 구매용량은 포장 전체 용량이고 레시피는 메뉴 하나에 사용하는 양이다. 구매가격 전체를 재료 1g·1ml 가격으로 취급하지 않는다.
- 실사 시점 이전의 판매·입고를 최근 실사 이후 변동으로 다시 빼거나 더하지 않는다. 시점이 불분명하면 정확한 잔량으로 단정하지 않고 확인 필요 상태를 표시한다.
- 최근 실사·레시피·납기·안전재고 자료가 없으면 발주량을 임의 산출하지 않고 부족한 입력을 알린다.
- 잔량이 음수로 계산되거나 계산상 구매 포장 단위보다 적은 잔량이 나와도 값을 숨기지 말고 기준 시점과 함께 표시한다. 음수 재고 허용·조정 정책은 미정이다.
- 시안 산식 설명에는 실사 이후 판매 사용량을 차감하는 항목이 명시되지 않았지만, 판매 기록과 재료 잔량을 연결하려면 필요하다. 이 차감은 제안이며 확정 전 검토가 필요하다.

### 직접 확인할 방법

- 위 예시 입력으로 예상 잔량 200ml, 목표량 400ml, 부족량 200ml, 발주 참고 1포장이 나오는지 확인한다.
- 최근 실사 전후에 입고·폐기·판매를 각각 추가해 실사 이후 기록만 반영되는지 확인한다.
- 단위 불일치, 재료 기준정보 누락, 실사 없음 상황에서 잘못된 발주량 대신 원인 안내가 나오는지 확인한다.

## F-07. 전체 자료 백업·복원

### 사용자가 하는 일과 입력

- 대시보드 또는 재고 화면의 백업·복원 기능을 선택한다.
- 백업은 거래·재고 기록뿐 아니라 메뉴·재료·레시피·공급사 등 프로그램에 저장된 자료 전체를 대상으로 한다.
- 복원할 백업 파일을 선택하고 기존 저장 자료가 대체될 수 있다는 안내를 확인한다.

### 프로그램이 하는 일

- 저장 자료를 백업 파일로 내보내고, 복원 시 파일을 검증한 뒤 전체 저장 자료를 복원한다.
- 시안의 제안은 JSON을 전체 보존·복원용, XLSX를 사람이 읽기 쉬운 내보내기용으로 구분한다. 파일 형식별 복원 가능 범위와 정확한 양식은 PRD에서 미정이므로 확정이 필요하다.
- 복원 과정에서 파일 구조, 필수 자료, 자료 간 참조가 유효한지 확인한다. 예를 들어 레시피가 존재하지 않는 메뉴나 재료를 참조하지 않는지 살핀다.

### 화면과 파일에 나오는 결과

- 백업 완료 후 생성된 파일과 대상 범위를 확인할 수 있다.
- 복원 완료 후 복원된 기록·기준정보의 범위와 결과를 확인할 수 있다.
- 복원 파일이 잘못된 경우 현재 저장 자료가 변경되지 않았음을 알 수 있어야 한다.

### 오류나 예외가 있을 때의 동작

- 쓰기·읽기가 실패하거나 파일이 손상되었으면 성공으로 표시하지 않고 원인과 재시도 방법을 안내한다.
- 파일 형식이나 데이터 구조가 맞지 않으면 복원 전에 중단한다.
- 복원은 기존 자료를 대체할 수 있으므로 실행 전에 대상과 영향 범위를 알린다. 부분 복원 여부는 미정이며, 제안은 검증을 모두 통과한 뒤 전체를 반영하는 방식이다.
- 백업이 일부 자료만 담았거나 버전 차이가 있어 복원할 수 없으면 누락 범위를 표시하고 현재 자료를 보존한다.

### 직접 확인할 방법

- 판매·비용·재고 기록과 메뉴·재료·레시피 기준정보를 준비해 백업한 다음 빈 저장 상태에서 복원하고 각 자료 수·내용이 일치하는지 확인한다.
- 손상된 파일과 잘못된 형식 파일로 복원을 시도해 중단 안내가 나오고 기존 자료가 그대로인지 확인한다.
- 복원 전 안내에서 기존 자료가 대체되는 범위를 알아볼 수 있는지 확인한다.

## 범위 구분과 미정 사항

### PRD에 포함된 핵심 기능

- 판매 기록 입력·수정·삭제
- 비용 기록 입력·수정·삭제
- 판매·비용·입고·폐기·실사 엑셀 양식 다운로드와 가져오기
- 재료·포장·결제 수수료만 반영하는 메뉴별 수익성 확인
- 일·주·월·분기·반기·연간 실제·예상 손익 조회
- 입고·폐기·실사 기록, 재료 잔량 및 발주 참고 정보 확인
- 전체 저장 자료의 저장·백업·복원 및 기본 입력 오류 안내

### 시안에만 있어 MVP에서 제외하는 항목

- 마감 체크리스트와 날짜 잠금
- POS 자동 연동
- 레시피 신규 등록·편집 화면
- 메뉴·손익 엑셀 내보내기 및 PDF 인쇄
- 발주서 인쇄·전송
- 예측 가중치 조정 및 ±10% 시나리오
- 매장 선택, 다중 매장, 역할·기기별 보기

### 확정 전에 남겨둘 항목

- 메뉴·재료·레시피·공급사 기준정보를 처음 준비하고 수정하는 방식
- 신규 판매 기록의 할인 입력과 순매출 처리
- 실제·예상 손익의 정확한 예측 방법, 비용계획 입력 경로, 일·주·월·분기·반기·연간 기간 경계
- 채널별 수수료율과 적용 시점. 시안마다 POS·포장 수수료율이 서로 다르며, 하나의 기준으로 확정할 수 없다.
- 메뉴 수익성의 과거 원가 스냅샷과 현재 레시피·가격 적용 기준
- 레시피가 판매채널별로 다를 때의 원가 계산 및 기준정보 누락 표시
- 재고 잔량 계산에서 최근 실사 이후 판매 사용량을 차감하는 기준, 폐기·입고의 시점·단위 처리, 음수 재고 정책
- 발주 목표량·예상 사용량 산정 기준과 구매 포장 단위 반올림 규칙
- 엑셀 시트·열·필수값, 중복 판정, 부분 오류가 있을 때 전체 또는 일부 반영할지 여부
- 백업 파일 형식별 복원 가능 범위와 백업 저장 위치
- 자료가 부분 기간만 있을 때 그래프·요약의 범위 표기 방식
- 삭제 확인·마감 자료 수정 허용 등 세부 정책

## 완료 기준

- 판매 기록을 날짜·메뉴·채널별로 입력·수정·삭제할 수 있고, 변경 결과가 저장되며 수익성·손익·재고 관련 조회에 일관되게 반영된다.
- 비용 기록을 입력·수정·삭제할 수 있고, 공통비로 기간 손익에 반영되며 메뉴별 직접비용에 임의 배분되지 않는다.
- 엑셀 양식을 내려받고 판매·비용·입고·폐기·실사 기록을 가져올 수 있다. 잘못된 행과 항목을 식별하고, 중복·부분 반영 동작은 합의한 정책에 따라 일관되게 처리한다.
- 메뉴 수익성의 직접비용 범위가 재료·포장·결제 수수료로 제한되고, 작은 기준 사례의 합계와 이익률이 정확히 맞는다.
- 일·주·월·분기·반기·연간 조회가 가능하며 실제값·예상값, 자료 없음·미마감 기간, 부분 연간 자료가 오해 없이 구분된다.
- 실제 손익과 예상 손익에서 월계획·일별 비용의 중복이 없고, 계산 결과가 합의한 작은 검산 사례와 일치한다.
- 입고·폐기·실사 기록이 저장되고, 가장 최근 실사 우선 원칙에 따라 잔량과 발주 참고 정보가 합의된 검산 사례와 일치한다.
- 누락·잘못된 입력, 기준정보 부족, 잘못된 파일 등 기본 오류에서 데이터가 조용히 잘못 반영되지 않고 사용자가 원인을 확인할 수 있다.
- 프로그램 저장 자료 전체를 백업·복원한 뒤 거래·재고 기록과 기준정보가 보존되며, 실패한 복원은 기존 자료를 훼손하지 않는다.
- 핵심 흐름인 **판매 입력 → 메뉴 수익성 확인 → 기간 손익과 재료 잔량 확인**을 완료할 수 있다.
