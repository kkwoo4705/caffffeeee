# 프렙 카페 운영 기록 프로그램 개발 계획

> **상태:** EPIC 1 사용자 확인 완료. EPIC 2는 구현·내부 계산 검사를 마쳤고 사용자 브라우저 확인을 기다린다. 4시간 중 EPIC 구현·사용자 확인은 100분으로 계획한다. 시간은 추정이며, 각 Story 시간에는 구현·자동 검사·화면 확인을 포함한다.
> **EPIC 진행:** EPIC 1만 사용자 확인까지 완료했다. EPIC 2는 브라우저 확인 전까지 완료로 표시하지 않는다. 사용자 확인 기록은 [테스트 결과](05_테스트결과.md)에 남긴다.

## EPIC·Story 수와 예상 시간

## EPIC 1. 운영 기록을 입력하고 저장하기 — 55분 — [x] 사용자 확인 완료

### Story 1. 운영자가 로그인해 기록 화면에 접근한다 — 15분

- **사용자가 할 수 있는 일:** 운영자 계정으로 로그인한다.
- **자동 검사:** 로그인 전 기록 접근을 막고, 로그인 후 접근을 허용하는지 확인한다.
- **화면에서 확인할 행동과 예상 결과:** 로그인하면 대시보드가 나타난다. 첨부된 가상 매장 자료는 확인용으로만 분리되며 실제 매장 기록으로 자동 등록되지 않는다.

### Story 2. 판매 기록을 입력·수정·삭제한다 — 15분

- **사용자가 할 수 있는 일:** 날짜·메뉴·채널별 하루 합계 판매 기록을 입력하고 수정·삭제한다.
- **자동 검사:** 날짜·수량·금액 누락과 형식 오류를 확인하고 저장 후 자료가 유지되는지 검사한다.
- **화면에서 확인할 행동과 예상 결과:** 수량 5개, 단가 100원, 할인 20원을 입력하면 총매출 500원, 순매출 480원이 표시된다. 저장 후 새로고침해도 기록이 유지되고, 수정·삭제가 조회에 반영된다.
- **입력 기준:** 시안 입력란에는 할인 입력이 없지만 자료에는 할인 기록이 있고 승인된 수익성 기준은 순매출을 사용한다. 정확성을 위해 할인 금액과 결제 수수료 금액 입력란을 추가하는 것으로 계획한다.

### Story 3. 비용 기록을 입력·수정·삭제한다 — 10분

- **사용자가 할 수 있는 일:** 날짜·비용 항목·금액을 입력하고 수정·삭제한다.
- **자동 검사:** 필수값과 날짜·금액 형식을 확인하고, 비용 계획과 실제 지출을 중복 합산하지 않는지 검사한다.
- **화면에서 확인할 행동과 예상 결과:** 비용 120원이 해당 월 실제 손익에 반영되고 메뉴별 수익성에는 배분되지 않는다. 새로고침 뒤에도 저장되어 있어야 한다.

### Story 4. 입고·폐기·실사 기록을 남긴다 — 15분

- **사용자가 할 수 있는 일:** 재료별 입고, 폐기, 실제 재고 수량을 기록한다.
- **자동 검사:** 재료와 단위가 맞는지, 수량이 올바른지 확인한다.
- **화면에서 확인할 행동과 예상 결과:** 입고·폐기·실사 기록이 서로 구분되어 표시되고 새로고침 후에도 남아 있다. 공란은 0으로 바뀌지 않는다.

**EPIC 완료 기준:** 운영자가 로그인해 판매·비용·재고 자료를 실제 저장할 수 있고, 잘못된 입력은 안내되며 저장 결과가 다시 접속해도 유지된다.

## EPIC 2. 메뉴 수익성·손익·재료 잔량을 확인하기 — 45분 — [ ] 구현·내부 검사 완료, 사용자 확인 대기

### Story 5. 메뉴별 직접 수익성을 확인한다 — 15분

- **사용자가 할 수 있는 일:** 메뉴별 순매출, 직접비용, 공헌이익과 이익률을 확인한다.
- **자동 검사:** 할인 후 순매출에서 재료·포장·결제 수수료를 빼는지, 공통비를 메뉴별로 배분하지 않는지 검사한다. 과거 실적은 당시 원가 기록을 사용한다.
- **화면에서 확인할 행동과 예상 결과:** FRD 예시인 판매가 4,091원, 직접비 522+110+115원, 판매량 5개에서 직접비 747원, 개당 공헌이익 3,344원, 이익률 약 81.7%, 합계 공헌이익 16,720원이 나와야 한다. 현재 메뉴 비교에는 현재 레시피·재료 가격을 사용한다.

### Story 6. 월별 실제 손익을 확인한다 — 15분

- **사용자가 할 수 있는 일:** 선택한 월의 실제 손익을 조회한다.
- **자동 검사:** 순매출·직접비·공통비 합계와 공란·자료 없음 구분을 검사한다. 계획과 실제 지출이 중복되지 않는지도 확인한다.
- **화면에서 확인할 행동과 예상 결과:** FRD 예시의 순매출 600원, 직접비 250원, 공통비 120원에서 영업이익 230원이 표시되어야 한다. 수정한 기록이 손익에 반영되고 새로고침 후에도 유지된다.

### Story 7. 최근 실사 기준 재고 잔량과 발주 참고를 확인한다 — 15분

- **사용자가 할 수 있는 일:** 재료의 예상 잔량과 발주 참고 수량을 확인한다.
- **자동 검사:** 최근 실사 이후의 입고·폐기·판매 사용량만 반영하고 단위와 포장량을 구분하는지 검사한다.
- **화면에서 확인할 행동과 예상 결과:** 실사 300ml + 입고 100ml − 폐기 50ml − 판매 사용 150ml에서 잔량은 200ml다. 하루 사용량 100ml, 납기 2일, 안전재고 2일, 포장 1,000ml일 때 발주 참고량은 1포장이다.
- **계산 기준:** 발주 목표량은 납기 기간과 안전재고 기간의 예상 사용량을 더해 잡고, 부족량은 구매 포장 단위로 올림한다.

**EPIC 완료 기준:** 실제 화면에서 **판매 입력 → 메뉴 수익성 → 월별 실제 손익 → 재료 잔량·발주 참고**가 연결되고, 위 검산값과 일치한다.

## 이번 시간 밖으로 미루는 PRD 필수 기능

다음은 PRD의 필수 기능이나 100분 범위에 포함하지 않고 후속 구현으로 미룬다. PRD의 수업 후 확장 후보와는 구분한다.

- 판매·비용·입고·폐기·실사 엑셀 양식 다운로드와 가져오기
- 전체 자료 백업·복원
- 월별 외 기간 조회와 손익 예상
- 실제 매장용 메뉴·재료·레시피 등 기준정보를 준비하는 방식

후속 구현 추천은 엑셀 가져오기 시 오류 행을 검증한 뒤 처리하고, JSON을 전체 복원용 백업으로 사용하며, 복원 오류 때 기존 자료를 보존하는 방식이다. 기간은 한국 기준 주간 월요일 시작, 분기·반기·연간은 달력 기준으로 나누는 안을 추천한다.

기준정보 등록 방법은 PRD에 기능이 정의되지 않았다. 수업 화면은 가상 샘플 확인용으로 두고, 실제 매장 운영 전에는 기준정보 준비 기능의 범위를 별도로 확정해야 한다.
