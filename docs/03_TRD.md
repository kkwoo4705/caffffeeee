# 프렙 카페 운영 기록 프로그램 기술 요구사항(TRD)

> **상태:** 운영용 구성 확정. 이 문서는 기술 구현 방식을 정하며, PRD·FRD의 기능 범위와 계산 기준을 변경하지 않는다. FRD에서 제안 또는 미정으로 남은 정책은 해당 정책이 확인될 때까지 구현 기준으로 확정하지 않는다.

## 사용할 기술과 선택 이유

- **Next.js App Router + TypeScript**: 웹 화면과 서버 처리를 한 프로젝트에서 구성한다. TypeScript는 자료의 종류를 미리 확인해 입력·계산 오류를 줄이는 도구다. Next.js 공식 시작 설정은 App Router, TypeScript, Tailwind CSS 등을 제공한다. [Next.js 설치 안내](https://nextjs.org/docs/app/getting-started/installation)
- **Tailwind CSS**: 시안의 화면 색상·간격·구성요소를 구현하는 화면 스타일 도구다.
- **Supabase PostgreSQL**: 판매·비용·재고·메뉴·재료처럼 서로 연결되는 자료를 지속적으로 보관하는 데이터베이스다. Vercel의 임시 실행 파일 공간이나 브라우저 저장소를 매장 기록의 원본으로 사용하지 않는다.
- **Supabase Auth**: 운영자 1명의 로그인을 처리한다. 다중 사용자 역할·권한, 다중 매장은 추가하지 않는다. 로그인 세션은 쿠키 기반으로 처리한다. Supabase는 Next.js 서버 렌더링 환경에서 쿠키 기반 인증을 안내한다. [Supabase Auth와 Next.js](https://supabase.com/docs/guides/auth/quickstarts/nextjs)
- **GitHub + Vercel**: GitHub를 코드의 기준 저장소로 하고, Vercel이 미리보기 및 운영 웹사이트를 배포한다. Vercel은 Git 저장소와 연결한 자동 배포를 지원한다. [Vercel Git 배포](https://vercel.com/docs/git)

현재 구성 비용은 공개 요금표 기준 **Vercel Pro 월 20달러 + Supabase Pro 월 25달러부터**, 합계 약 45달러부터로 예상한다. 세금·사용량·추가 자원 비용은 별도다. Vercel Hobby는 개인·비상업 용도 제한이 있고, Supabase Free 프로젝트는 1주 비활성 후 일시 중지될 수 있어 실제 매장 운영 자료에는 유료 구성을 선택했다. Supabase Pro는 일일 데이터베이스 백업을 제공한다. [Vercel 요금](https://vercel.com/pricing), [Vercel 이용약관](https://vercel.com/legal/terms), [Supabase 요금](https://supabase.com/pricing), [Supabase 백업](https://supabase.com/features/database-backups)

## 처리 순서

1. 운영자가 로그인하고 판매·비용·입고·폐기·실사 기록을 화면에 입력하거나 엑셀 양식을 선택한다.
2. 서버가 입력값, 날짜, 식별 대상, 수량 단위, 관계된 기준정보를 검증한다. 자료의 공란은 0으로 바꾸지 않는다.
3. 검증에 통과한 변경을 데이터베이스에 저장한다. 저장에 실패하면 성공으로 보이지 않게 하고 오류를 안내한다.
4. 화면 조회 요청에 맞춰 필요한 기간·메뉴·재료의 자료를 데이터베이스에서 읽는다.
5. 수익성·손익·재고 계산은 FRD에서 최종 합의한 기준만 사용하고, 결과를 화면에 표시한다. 예상값은 실제값과 구분하고 자료가 없는 기간을 0으로 추정하지 않는다.
6. 백업은 저장 자료 전체를 파일로 내보낸다. 복원은 파일 구조·필수 자료·자료 간 연결을 검증한 뒤 진행한다.

판매는 날짜·메뉴·채널별 하루 합계 단위다. 금액은 원화·부가세 제외, 재료 단위는 g·ml·개이며, 구매 가격은 포장 전체 금액이고 레시피 사용량은 메뉴 1개당 양이다. 첨부된 엑셀과 JSON은 같은 샘플이므로 시연·검증 때 한 형식만 사용한다. 이 샘플을 실제 매장 자료로 자동 등록하지 않는다.

## 주요 파일이 맡는 일

- `app/`: 대시보드, 판매·비용, 메뉴 수익성, 손익, 재고, 로그인 및 요청 처리 화면
- `components/`: 시안에 맞춘 공통 버튼·입력칸·표·그래프 등 화면 부품
- `lib/domain/`: 승인된 수익성·손익·재고 계산, 날짜·단위·필수값 검증
- `lib/import/`: 엑셀 양식 생성, 파일 읽기, 미리보기 자료 검증
- `lib/backup/`: 전체 백업 생성, 복원 전 검사와 복원 처리
- `lib/db/`: 서버에서 데이터베이스에 접근하는 공통 처리
- `supabase/migrations/`: 데이터 구조·인덱스·접근 정책의 버전 이력
- `tests/`: 계산 기준, 저장·가져오기·복원, 핵심 사용 흐름의 자동 확인
- `.env.example`: 필요한 환경 변수 이름만 제공하며 비밀값은 포함하지 않음

이는 코드 저장소의 권장 구성이다. 실제 파일·테이블 이름과 상세 구조는 구현 때 정하되, PRD·FRD에 없는 사용자 기능을 추가하지 않는다.

## 데이터 저장·이동·복구

- **주 저장소:** Supabase PostgreSQL에 판매·비용·재고 이벤트·초기 재고·비용계획·영업달력과 메뉴·재료·레시피·공급사 등 저장 대상 자료를 보관한다. ID, 기록 날짜, 메뉴·재료 연결, 단위를 보존한다.
- **화면 조회:** 날짜·메뉴·재료 등 실제 조회 조건에 맞춘 인덱스를 둔다. 인덱스는 해당 조건으로 찾는 속도를 높이는 데이터베이스 구조다. 필요하지 않은 전체 자료를 매번 내려받지 않으며, 목록은 나눠 읽는다.
- **엑셀 가져오기:** PRD 범위에 따라 판매·비용·입고·폐기·실사 기록을 지원한다. 메뉴·재료·레시피·공급사 기준정보를 엑셀로 가져오는 기능은 추가하지 않는다. 원본 샘플과 동일한 엑셀·JSON 데이터를 함께 가져오지 않도록 안내한다.
- **가져오기 일관성:** 읽기·형식 검증·오류 행 표시·저장 단계로 구분한다. 중복 기준, 오류 행과 정상 행의 부분 반영 여부는 FRD에서 미정이므로 임의로 정하지 않는다. 정책 확정 후 한 작업 안에서 데이터가 일부만 잘못 반영되지 않도록 데이터베이스 트랜잭션(작업 묶음 저장)을 사용한다.
- **전체 백업:** 거래·재고 기록과 기준정보 전체를 대상으로 한다. 시안에 JSON·XLSX가 표시되어 있으나, FRD상 형식별 복원 가능 범위는 미정이다. 제안은 JSON을 손실 없는 전체 복원용, XLSX를 사람이 확인하기 쉬운 형식으로 제공하는 것이다. 이 제안은 파일 형식 정책 승인 전까지 확정된 요구가 아니다.
- **복원:** 기존 자료를 대체할 수 있음을 미리 표시하고, 복원 파일 형식·참조 관계·필수 자료를 확인한다. 제안은 검증이 끝나기 전에 현재 자료를 지우지 않고, 복원 실패 시 기존 자료를 보존하는 전체 단위 처리다. 부분 복원 여부와 파일별 허용 범위는 FRD 결정에 따른다.
- **공급자 백업:** Supabase의 관리형 일일 백업은 장애 복구를 돕는 별도 안전망이다. PRD의 운영자 전체 백업·복원 기능을 대신하지 않는다. Pro의 일일 백업 보관기간은 현재 7일이며, 장기 보관은 운영자가 내려받은 전체 백업 파일로 별도 관리해야 한다. [Supabase 백업](https://supabase.com/features/database-backups)

## 정보 보호

- 로그인하지 않은 요청에는 운영 자료 접근을 허용하지 않는다. 단일 운영자 계정만 두고 다중 사용자 권한 기능은 구현하지 않는다.
- 데이터베이스의 모든 노출 테이블에 RLS(행 단위 접근 정책)를 설정한다. 운영자 인증 상태에 맞춰 읽기·쓰기 권한을 제한하고, 익명 접근을 차단한다. Supabase 문서는 노출 테이블에 RLS와 권한 설정을 적용하고 비밀 키를 브라우저에 노출하지 않도록 안내한다. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)
- 데이터베이스 비밀 키와 인증 비밀값은 Vercel 서버 환경 설정에 저장한다. 화면으로 전달되는 코드, GitHub 커밋, 로그에는 넣지 않는다.
- 통신은 HTTPS를 사용한다. 세션은 안전한 쿠키 설정을 적용한다.
- PRD·FRD 범위에 없는 고객 개인정보·카드정보는 수집하지 않는다. 오류 로그에는 로그인 비밀값, 전체 백업 내용, 매출 원문을 남기지 않는다.
- 미리보기와 운영 환경의 데이터베이스 자격 증명을 분리한다. 실제 매장 자료는 운영 환경에만 둔다.

## 오류 대응

- **입력값 오류:** 저장 전에 필드와 행, 수정 사유를 안내하고 잘못된 자료는 계산에 반영하지 않는다.
- **기준정보 누락·단위 불일치:** 0으로 대체하지 않는다. 결과 계산을 보류하거나 불완전 상태로 표시하고 필요한 기준정보를 알린다.
- **중복 가능성:** 판매·비용·재고 중복으로 합계가 부풀려지지 않도록 경고한다. 자동 차단·건너뛰기 기준은 FRD에서 결정한 정책을 따른다.
- **저장소 연결·시간 초과:** 저장 성공으로 표시하지 않는다. 안전한 재시도 방법을 제공하고 동일 작업이 중복 생성되지 않게 처리한다.
- **엑셀 오류:** 지원하지 않는 파일, 필수값 누락, 날짜·숫자·단위 오류를 행 단위로 알려준다. 오류 행 일부 반영 여부는 합의한 가져오기 정책대로 처리한다.
- **복원 오류:** 손상·미지원 파일이나 관계가 맞지 않는 자료는 복원을 중단하고 기존 자료를 보존한다.
- **배포 오류:** 미리보기 빌드 실패는 운영 배포로 넘기지 않는다. 운영 반영 후 문제가 발생하면 이전 정상 배포로 되돌릴 수 있도록 배포 이력을 유지한다.
- 오류 로그에는 발생 시각, 기능 구분, 안전한 오류 코드 등 진단 정보만 기록하고 사업 데이터를 불필요하게 복제하지 않는다.

## 배포 방법

1. GitHub 저장소에 변경을 커밋한다.
2. 변경 브랜치를 Vercel 미리보기 환경에 배포해 화면과 기능을 확인한다.
3. 확인된 변경만 운영 브랜치에 반영하고 Vercel 운영 배포를 진행한다.
4. 데이터 구조 변경은 버전이 기록된 마이그레이션으로 적용한다. 운영 데이터 구조를 바꾸기 전에는 복구 가능한 전체 백업을 확인한다.
5. Vercel의 미리보기·운영 환경에는 각각 해당 환경의 Supabase 주소·키를 설정한다.

현재 기준의 기본 월 비용은 Vercel Pro 20달러와 Supabase Pro 25달러부터로 약 45달러부터다. 사용량·세금·추가 컴퓨팅 비용은 달라질 수 있으므로 배포 시점에 공급자 요금표를 다시 확인한다. [Vercel 요금](https://vercel.com/pricing), [Supabase 요금](https://supabase.com/pricing)

## 확인 방법

- **계산 정확성:** FRD의 승인된 작은 검산 사례와 화면 결과를 대조한다. 할인, 채널 수수료, 예측, 실사 후 재고 산식 등 미정된 계산 기준은 먼저 확정한 뒤 그 기준 사례를 검사한다.
- **자료 저장:** 판매·비용·재고 기록을 입력·수정·삭제한 뒤 다시 접속해도 결과와 기간 집계가 유지되는지 확인한다.
- **가져오기:** 정상 파일, 필수값 누락, 잘못된 날짜·단위, 중복 의심 파일을 각각 처리해 행별 결과와 저장 결과가 합의한 정책과 맞는지 확인한다.
- **백업·복원:** 거래·재고·기준정보 전체를 백업하고 복원해 자료 수와 연결이 보존되는지 확인한다. 손상 파일 복원 시 기존 자료가 그대로인지 확인한다.
- **정보 보호:** 로그인 없이 자료 요청이 거부되는지, 데이터베이스 비밀 키가 브라우저 응답과 공개 저장소에 없는지 확인한다.
- **핵심 흐름:** 판매 기록 입력 → 메뉴 수익성 → 선택 기간 손익 → 재료 잔량·발주 참고까지 일관되게 이어지는지 확인한다.
- **처리 속도:** 첨부 샘플 수준(판매 6,112건, 비용 3,560건, 재고 기록 1,515건)으로 대시보드와 기간 조회를 측정한다. 목표 응답시간은 PRD·FRD에 정해져 있지 않으므로 임의의 수치를 요구하지 않고, 측정 결과를 바탕으로 별도 합의한다.

### 구현 전에 FRD에서 확정할 정책

기술 구성은 확정했지만 아래 항목은 TRD에서 임의로 채우지 않는다. 각 항목의 최종 기준은 PRD·FRD 확인을 거쳐 구현에 반영한다.

- 신규 판매 할인 입력과 과거 원가·수수료 기록 사용 기준
- 채널별 수수료율, 손익 예상 방법, 비용계획을 예상 손익에 반영하는 방식
- 재고 잔량 계산의 실사·입고·폐기·판매 사용 반영 방식과 발주 참고 산식
- 엑셀 중복 판정 및 일부 오류가 있을 때 가져오기 처리 방식
- JSON·XLSX 백업 형식별 복원 지원 범위와 전체·부분 복원 정책
- 기간 경계, 자료가 일부 기간만 있을 때의 표시 기준
